# I16 — Trade fairs, associations and programmes

Agent: vibe-a17f (Vibe Code). Branch: `intel/I16-trade-fairs-associations-and`.

## What I built

* `intel/collectors/networks.py` — the `networks` collector (produces `networks.*` only): five
  independent plugins behind one `run`, each with its own error handling so a broken plugin never
  kills the others:
  1. `_plugin_own_site_fairs` — trade fairs the company announces on its own site (grade B).
     Walks the homepage plus up to 6 news/event pages discovered by link-path hints (`news`,
     `eventi`, `fiera`, `presse`, ...). A fact requires the fair brand AND the company name inside
     the same quoted sentence (word-boundary match against a fair vocabulary: ACHEMA, Fruit
     Logistica, SPS, MECSPE, Ipack-Ima, Interpack, Ecomondo, ...).
  2. `_plugin_group_site_fairs` — fairs announced on a group site (parent / sister company,
     grade C). The group site is discovered from links on the company's own about/company page
     (external, non-social hosts) — nothing hard-coded; the golden NW-02 source (mottcorp.com
     ACHEMA 2015 article) is found through ASCO's own `/Home/Company` page linking to Mott.
     The site's WordPress-style `?s=<brand>` search is tried, then fair posts are fetched and
     quote-grounded.
  3. `_plugin_own_site_associations` — association memberships stated on the company's own
     pages (grade B) via membership vocabulary (`associazione`, `member of`, `Verband`, ...).
  4. `_plugin_ipcei_hydrogen` — the EU IPCEI Hydrogen matchmaking directory (grade A public
     register): the directory's own `?combine=<brand>` filter, entry-page discovery by slug
     match, then two facts: the programme entry (quote = company name + legal address block)
     and the register's own "Association's membership:" line (this is what captures H2IT for
     ASCO). A miss after a successful lookup is `checked_absent`.
  5. `_plugin_cordis` — CORDIS search probe. The public search page is JS-rendered, so a hit
     without quotable text is recorded as an error (a lead, not a fact) and a clean miss as
     `checked_absent`. No CORDIS fact was emitted in any live run; the plugin is deliberately
     conservative.
* `tests/test_intel_networks.py` — 9 offline tests with recorded pages (zero network): own-site
  fair extraction, group-site fair extraction, IPCEI entry + association line, IPCEI
  checked-absence, paraphrase-never-emitted, crashing-plugin isolation, prefix discipline
  (`check_result`), the merge-of-evidence rule (same fair on two pages = one fact), helper
  unit tests.

## Decisions taken and why

* **No general search engine.** DuckDuckGo (html and lite), Brave, Bing HTML and Bing RSS all
  soft-block or degrade for the honest bot UA from this sandbox; SearXNG instances disallow
  `?q=` in robots.txt; paulgo.io robots-disallows query URLs. The collector therefore uses
  deterministic, robots-friendly routes: own site, group site `?s=` search, and the IPCEI
  register's own filter. A keyed search provider (roadmap decision G1) would raise coverage
  on fair history (older editions, third-party exhibitor lists); that decision stays with GG.
* **RNA state aid: no plugin.** `adapters/rna_state_aid.py` is already wired into
  `company_service.py` (line 291), so the ticket's "unwired adapter" concern does not apply;
  duplicating it as a collector would be a second producer for the same fact.
* **LLM not required.** The board lists `llm` in needs, but no key was available; the collector
  works fully without it (it never declares `requires=("llm",)`, matching the sibling
  collectors). An LLM could later widen fair-vocabulary matching; the deterministic core stands.
* **Group-site trust rule.** A group page is only evidence when the company's brand appears
  inside the quoted sentence naming the fair; this is what keeps Mott's blog from attaching
  unrelated Mott fairs to ASCO.

## Not done / open points

* CORDIS: no fact can be emitted until the JS-rendered search is solved (browser fallback,
  ticket I05/D33 territory, or the CORDIS API which needs a key).
* Association member directories (UCISAP, ANIMA, Federmacchine, H2IT's own site) publish
  nothing readable to a polite non-JS fetcher: UCISAP 404s its recorded member URL, H2IT's
  WordPress search returns "nothing matched". Membership facts currently come only from the
  company's own site and the IPCEI register line.
* Trade-fair coverage is limited to the fair vocabulary in the module; a long-tail fair not
  in `FAIR_STRONG` is missed (own-site sentences naming it are not parsed).
* The collector was not run through the Node worker fleet; it runs where the orchestrator runs
  (Python `requests` only), per roadmap invariant 3.1.5.

## What the next agent must know

* The plugin contract is: `plugin(ctx, company, result) -> None`, append to `result.facts` /
  `result.checked_absent` / `result.errors`; wrap each plugin in the `PLUGINS` tuple; `run`
  already isolates crashes. Every fact must pass `quote_in_text(quote, page.text)` before the
  Evidence is built, and the fair keyword AND the company token must be inside the quote.
* Fair facts are grouped by `(fair, year)` and merged by the Ledger (same key+value = one fact
  with several URLs as evidence); the value is `{"fair": ..., "year": ...}` only — no `source`
  field, or the same fair on two pages becomes two facts.
* The IPCEI plugin needs the module constant `IPCEI_BASE` untouched for tests to monkeypatch;
  tests overwrite it to point at recorded pages.
