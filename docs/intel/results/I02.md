## What I built
* `intel/ledger.py`: `Fact`, `Evidence`, `Ledger`, `quote_in_text`, `load_ledger` / `save_ledger` (one `raw_import_records` row per company, dataset `crawler_deep_profile`, no schema change). Rules enforced in code: a web fact needs a URL and a verbatim quote of 12+ characters; grade A may cite a registry reference; unverified grade D cannot claim confidence above 0.5; the same (key, value) merges evidence; single-valued keys with two values surface as conflicts; staleness helper; fact cap.
* `intel/collector.py`: `Collector`, `CollectorContext`, `CollectorResult`, `Budget`, `check_result` (a collector may only emit under its declared prefixes), `discover()` (auto-registration; a duplicate name is an error).

* `scripts/intel_run.py`: runs one or all collectors against one company from a JSON fixture, builds an in-memory ledger, prints facts, writes a JSON file; never touches the database.
* `scripts/intel_board.py`: the diagnosis board's engine (`scripts/board.py`, untouched) pointed at `docs/intel/board.json`, with `I<nn>` ids and its own claim banner. `docs/intel/board.json`: 34 tickets.
* `intel/collectors/site_headers.py`: reference collector. Live on ASCO: `digital.web_server = Microsoft-IIS/10.0`, `digital.web_framework = ASP.NET`, `digital.hosting_panel = PleskWin`, each quoted from the response headers. Closes golden DG-02 (the existing detector said "absent").
* `tests/test_intel_ledger.py`, `tests/test_intel_board.py` (shipped-board integrity, dependency cycles, write-scope overlap of parallel-ready tickets, an atomic claim against a throwaway bare repository).

## Decisions taken and why
* Ledger stored as a blob, not a table: no migration on the live database (OP-013), same mechanism as every crawler, and it can be promoted to a table later without changing the contract.
* Collectors are plugins discovered by import, so adding one never edits `company_service.py`, the file every new source used to collide on.
* The board reuses the diagnosis engine through a shim instead of forking it, so fixes to the engine benefit both.
* `requirements.txt` was left alone: bs4, lxml and pypdf are installed locally but not listed. I05 decides what the hosted app needs.
