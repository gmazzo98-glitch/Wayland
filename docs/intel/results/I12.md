# I12 — Ownership classification and group flag: who really controls the company

Agent: vibe-c727 · Branch: `intel/I12-ownership-classification-and` · Roadmap: `docs/INTEL_ROADMAP.md` § I12 (R4).

## What I built

* `intel/ownership.py` — the pure AIDA classifier. `classify_ownership(company, aida_blob) -> OwnershipProfile`: ultimate owner type (`family | family_holding | private_equity | industrial_group | listed_group | public_body | unknown | no_data`), control chain (levels, stakes, countries), `controlled_subsidiary` with its basis, foreign control, family share, group size, independence class. Types holders by AIDA type cell (`Persone fisiche o famiglie`, `holding di investimento`, `Società quotata`) with high-precision name heuristics (PE funds on word boundaries; listed parents only with an exchange token or a well-known listed name — `Inc.`/`Corp.` alone is NOT enough). `profile_to_facts` renders the ledger value; `load_aida_blob_for` reads one blob read-only; `raw_counts` + `distribution_report` implement the roadmap's own 533/139 counting rules for the portfolio run; `python -m intel.ownership --db [--json out.json]` is the portfolio CLI.
* `intel/collectors/ownership.py` — collector `ownership` (ticket I12, produces `ownership.` + `locations.`, requires web). Layers: (1) grade-A `ownership.classification` + `ownership.controlled_subsidiary` from the AIDA blob when `company["aida_blob"]` is injected; (1b) grade-B `locations.footprint` — foreign branches/subsidiaries the company's own pages state, found on fixed + navigation-discovered profile pages (including language variants, e.g. `/en/company/`); (1c) web-only control chain: own-site group claims (`ownership.site_group_claim`, e.g. "parte del Gruppo X", "part of an industrial group named X"), own-site acquisition statements (`ownership.site_acquisition`), deal-press search (`ownership.previous_owners`, the acquirer, `ownership.parent_people` — executives quoted in deal announcements, e.g. "Boris Levin, CEO of Mott Corporation"), and the acquirer's own deal page (`_owner_site_deal_page`: owner domain resolved first from the company's own external links, then search; site search `?s=brand`; entity-verified) — plus grade-A `ownership.subsidiary_listing` from SEC EDGAR full-text when a listed parent's filing names the company. Search goes through `ctx.search` when the orchestrator supplies one, else falls back to the shared `intel/search.py` SearchClient (SEC + Google News + GDELT + DuckDuckGo). Checked-but-not-found keys are `checked_absent` (`ownership.site_group_claim`, `ownership.site_acquisition`, `ownership.classification`, `ownership.controlled_subsidiary`, `ownership.previous_owners`, `locations.footprint`, `ownership.parent_people` when a corporate owner exists).
* `tests/test_intel_ownership.py` — 15 offline tests: classifier on 5 blob archetypes (listed chain, family, family holding, PE, no data), the 533/139 raw-count rules, distribution aggregation, golden-shaped hand-labelled archetypes (Bertazzon, Isolcell, Pomini, Eurosicma styles), and collector runs on recorded pages (EDGAR EX-21, PR-style deal text, BeBeez-style Italian deal text) with quote-grounding asserted for every emitted fact.

## Decisions taken and why

* **Locations footprint in this ticket**: golden LO-01 is assigned to I12, so `locations.footprint` is produced here from own-site history pages (where the group created entities). Declared in the collector's `produces` and checked with the board's write scope in mind (`locations.*` facts only, no other collector's keys).
* **AIDA blob injection**: `intel_run.py` does not read databases and the orchestrator (I30) does not exist yet, so the classifier path accepts the blob through `company["aida_blob"]`. The portfolio acceptance (953 blobs, 533/139 reproduction) is implemented and unit-tested but could not be RUN in this session: no `.env` / DATABASE_URL here (preflight noted `.env` not found). To run: `python -m intel.ownership --db --json /tmp/i12_distribution.json` on a machine with read access. The 533/139 definition is implemented exactly as the roadmap states it and covered by tests.
* **DDG/GDELT blocked**: I extended the fallback search to the shared `intel/search.py` client instead of writing a new provider, and read BeBeez's public search page through the polite fetcher (the same source class the I13 events collector already uses). No CAPTCHA solving, no login, robots.txt honoured by the fetcher.
* **Owner-site deal pages**: when an owner is identified, its domain is resolved FIRST from the external links on the company's own pages (acquired companies usually link their parent), then from search. This is generalizable and found `mottcorp.com` from ASCO's own `/Home/Company` links.
