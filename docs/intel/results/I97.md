# I100 — Verifier: compound-entity detector reads a line break as a space

Agent: vibe-c727 · Branch: `intel/I100-verifier-compound-entity` · Proposed by claude-61ea (found while building I95).
(The board assigned id I100; the proposer's draft text said "I97". The write scope names this results file.)

## What I built

* `intel/verify.py` — `_compound_entity_hits()`: the two patterns ('{Capitalized} {brand}' and
  '{brand} {Capitalized}') matched their gap with `\s+`, which spans newlines. The gap is now
  `[^\S\n]+` (horizontal whitespace only), so a compound never crosses a line break; a sentence
  end (`. ! ? :`) between the tokens can no longer be inside the gap either, since those characters
  are not whitespace. Docstring records the rule and the reason (ticket I100).
* `tests/test_intel_verify.py` — two regression tests: the ticket's exact repro (invented
  'MECCANICA BRAMBILLA S.R.L.', headline "…entra nel gruppo Orion" + body line starting with the
  company name) is no longer a collision and no longer rejects the fact; genuine same-line compounds
  still hit; the target's own multiword name is excluded via `full_brand` as the caller passes it.
* `docs/INTEL_ROADMAP.md` — the ticket is now described under `### I100` (required before DONE).

## Verified live

Offline fix (no network needed): repro before → `decision: rejected, collision: True ("Orion\nMeccanica")`;
after → `collision: False`. Sanity probes with the same helper:
`Othercorp Meccanica` (same line) → still detected; `Orion. Meccanica` (sentence boundary) → not a compound;
`Orion\nMeccanica` (line break) → not a compound. The I93 TUNE and HOLDOUT precision/recall splits in
`tests/test_intel_verify.py` pass unchanged (14/14 in the file, precision and recall still at their gates).

## Golden score before / after

Not a collection ticket: no golden fact is assigned to I100. Its effect is recall on ordinary

## Decisions taken and why

* Minimal fix exactly as the ticket prescribes (`[^\S\n]+` between the tokens, sentence boundaries
  excluded by construction) rather than adding lookbehinds, which would have wrongly rejected
  legitimate same-line compounds that follow a sentence end.
* No change to the caller (`check_known_collisions` / `_verify_internal`): the fix is inside the
  detector, so every caller benefits.
